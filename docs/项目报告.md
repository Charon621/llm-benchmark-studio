# LLM Benchmark Studio 项目报告

> 本文档面向评审者与面试官，从问题、设计取舍与验证策略的角度梳理项目；
> 功能清单与操作说明见 [README](../README.md)，验收记录见 [视觉工作流与验收_2026-10-15](视觉工作流与验收_2026-10-15.md)。

## 1. 选题背景与问题定义

评测大模型应用时，"跑个分"式的做法有三个系统性缺陷：配置漂移（两次实验的模型参数、提示词版本、数据无法对齐）、黑箱评分（LLM Judge 给一个数字却不留复核路径）、成本失控（重试与并发调用没有预算账本）。

本项目把问题定义为：**在 Promptfoo 原生引擎之上，构建一个面向审计的本地中文评测工作台**，使每一次实验都可复现、可解释、可中断、可核算成本——而不是另起炉灶写一个评测框架。

## 2. 系统设计

### 2.1 总体结构

Express 本机服务（默认端口 8812）+ 无构建步骤的中文 Web 工作台；评测执行放在可取消的 worker 子进程中，调用 Promptfoo 0.124.1 的原生 `evaluate()`；自定义 provider 适配层统一承载 Mock、实时 HTTP（OpenAI Chat / Anthropic Messages 原生协议）与 AgentLab 联动三种来源；所有请求经过共享预算适配层（超时、重试、成本预留）。

### 2.2 关键设计决策

| 决策 | 备选方案 | 选择理由 |
|---|---|---|
| 调用 Promptfoo 原生引擎 | 自研执行器 | 断言生态（`is-json`、`contains`、`javascript`、`llm-rubric`）与结果结构是社区标准；自研等于重复造轮子且失去互操作性 |
| 每单元原子落盘（rows.json / ledger.json / snapshot.json 分离） | 结束时一次性写 | 长实验取消、断电、重启后已完成单元不丢；ledger 损坏不阻止读取已完成结果 |
| 冻结配置 + SHA256（模型参数、提示词版本、数据 hash、源码 hash） | 记录"大致参数" | 复现的充分条件是完整配置快照，而不是配置片段 |
| 重试后成功的单元总费用记**未知** | 把成功那次的 usage 当总费用 | 失败尝试可能已计费；`successful_attempt_*` 保留成功那次的已知值，不冒称整体 |
| 人工复核与自动评分分离存储 | 覆盖自动评分 | 自动结果保持原样，人工分类可随时修订并反映到导出 |
| worker 环境剔除全部密钥变量，仅经 IPC 取本场凭证 | 子进程继承环境 | 最小化密钥暴露面；snapshot 与导出不携带密钥 |

### 2.3 评分体系的三层语义

规则断言检查预定义要求；参考事实词覆盖是**探针不是准确率**（可能漏同义表达，也可能上下文错误仍命中）；可选的 `llm-rubric` Judge 独立记分并保留原始理由，Judge 故障标记"评估失败"并从质量分母剔除，而不是折算成 0 分。稳定性定义为重复组中完全相同输出的众数比例，且明确"稳定地重复错误不是准确率"。

## 3. 成本与预算账本

`max_calls` 覆盖生成、重试与 Judge；429/5xx/超时有限退避，400 类请求错误不盲目重试。已知价格时并发调用先预留保守成本再发请求；美元预算要求所有启用的实时 provider（含 Judge）都配置价格。`cost_audit` 单列 Judge 请求、实验总费用与已知覆盖率——只要任一尝试费用未知，完整总费用保持 null。这是"诚实显示未知"原则在成本维度的落点。

## 4. 测试与验证策略

本地自动化覆盖：24 单元 Mock 原生 Promptfoo 矩阵 + 16 单元 OpenAI/Anthropic 混合协议矩阵、模型 CRUD 与凭证版本恢复、会话隔离（实验全部入口）、旧记录迁移、JSON 错误不反射密钥、SSRF/DNS 固定/重定向拒绝、HTTP 错误分类、重试与未知费用语义。测试 HTTP 服务是本机夹具，不使用云端密钥；GitHub Actions 在 Windows / Ubuntu 的 Node 24 上运行。

## 5. 证据边界声明

**已验证**：Mock 流水线、原生 Promptfoo 多选矩阵、本地协议夹具、工程闭环（恢复、取消、导出、复跑）。
**未验证**：任何真实云端模型的质量结论、单/多 Agent 架构优劣、统计显著性——这些需要显式授权实时调用、预注册协议与人工事实核验。所有已保存报告均明确标注执行模式；Mock 分数用于验证工程管线，不用于声称模型能力。

| 项 | 状态 |
